## 1. Aggiungere una nuova pagina

Tre passi, in ordine:

> **Regole strutturali** della pagina:
>
> 1. (`KEIJO-PAGE-WRAPPER-IS-CANONICAL-ROOT`) il root di ogni pagina è
>    `<keijo-page-wrapper>`. Il wrapper è **fisso** (flex-col, gap-2, w-full,
>    no max-width). L'**unico** input è `[scrollable]` (default `true`; passa
>    `false` quando dentro c'è una `<keijo-table>` con sticky scroll).
> 2. (`KEIJO-CONTENT-IN-LOGICAL-SECTIONS`) il contenuto va sempre raggruppato
>    in una o più `<keijo-page-section-wrapper>`. Page-wrapper e
>    section-wrapper condividono lo stesso gap (gap-2) per consistenza
>    verticale tra macro-sezioni e contenuto interno. Vale anche con una
>    sola sezione. Niente componenti come figli diretti del page-wrapper
>    fuori da una `<keijo-page-section-wrapper>`.
>
> Modes della section: `[mode]="'card'"` (default — white card chrome) o
> `[mode]="'plain'"` (no chrome, solo flex-col gap-2 — per puro raggruppamento
> di layout, es. searchbar+tabella+paginazione).
>
> La section può anche avere `[title]` (h2 in alto) e `[buttons]: SectionActionButton[]`
> (footer, flex-row-reverse, `buttons[0]` rightmost = primary). I bottoni hanno
> `variant: 'accent' | 'warning' | 'error' | 'default'`, label sempre visibile.
> Usalo per pattern view ↔ edit inline (cambia [title], swappa il content via
> *ngIf, aggiorna [buttons]) senza creare sotto-rotte di edit.
>
> Il **titolo della pagina vive nell'header** (`HeaderTitleService.set('…')` in
> `ngOnInit`) — **niente `<keijo-page-title>` nel body** (sarebbe un doppio titolo
> con quello dell'header: `KEIJO-NO-DUPLICATE-PAGE-TITLE`).
>
> ```html
> <keijo-page-wrapper>
>   <keijo-page-section-wrapper mode="plain">
>     <keijo-search-bar [search]="searchControl" />
>     <keijo-list-items-wrapper>…</keijo-list-items-wrapper>
>     <keijo-pagination [paginator]="paginator" />
>   </keijo-page-section-wrapper>
> </keijo-page-wrapper>
> ```

**a) Crea il componente** in `src/app/pages/<nome>/<nome>.component.ts`:

```ts
import { Component, OnInit, inject } from '@angular/core';
import { PageWrapperComponent, PageSectionWrapperComponent } from '@keijo/ui';
import { HeaderTitleService } from '../../services/header-title.service';

@Component({
  selector: 'app-clienti',
  standalone: true,
  imports: [PageWrapperComponent, PageSectionWrapperComponent],
  // Titolo nell'header (HeaderTitleService) — niente <keijo-page-title> nel body.
  template: `
    <keijo-page-wrapper>
      <keijo-page-section-wrapper mode="plain">
        <!-- contenuto -->
      </keijo-page-section-wrapper>
    </keijo-page-wrapper>
  `,
})
export class ClientiComponent implements OnInit {
  private readonly headerTitle = inject(HeaderTitleService);
  ngOnInit(): void { this.headerTitle.set('Clienti'); }
}
```

**b) Aggiungi una route lazy** in `src/app/app.routes.ts`:

```ts
{ path: 'clienti', loadComponent: () => import('./pages/clienti/clienti.component').then(m => m.ClientiComponent) },
```

**c) Aggiungi la voce nella sidebar** in `src/app/shell/sidebar-routes.ts`:

```ts
import { person } from '@keijo/ui/icons';

// dentro SIDEBAR_ROUTES
{ icon: person, label: 'Clienti', path: '/clienti' },
```

## 2. Comporre un form

Usa `<keijo-form-wrapper>` + `<keijo-form-row>` come container, e `<keijo-input>` / `<keijo-select>` / `<keijo-textarea>` / `<keijo-checkbox>` come campi. Tutti compatibili con `FormControl`/`FormGroup` reattivi.

```ts
form = new FormGroup({
  nome: new FormControl(''),
  email: new FormControl(''),
});
```

```html
<keijo-form-wrapper [formGroup]="form">
  <keijo-form-row [cols]="2">
    <keijo-input [formControl]="form.controls.nome"  label="nome"  id="nome" />
    <keijo-input [formControl]="form.controls.email" label="email" id="email" />
  </keijo-form-row>
</keijo-form-wrapper>
```

CTA primaria (Salva, Invia) **in fondo al form-wrapper**, allineata a destra.

## 3. Liste e tabelle

**Default**: liste = `<keijo-entity-list-item>` dentro `<keijo-list-items-wrapper>`. Usa la tabella **SOLO** se l'utente lo chiede esplicitamente.

- **`<keijo-entity-list-item>` (default)** — list compatta con primary/secondary/actions templates. **Sempre con `[expandable]="true"`** così su mobile il contenuto secondario diventa togglable (vedi pattern della demo). Adatto a item con identità "atomica" (cliente, macchina, campagna…).
- **`<keijo-table>`** — solo su richiesta esplicita "voglio una tabella". Adatta a dati colonna-uniformi senza secondario rilevante.

```html
<keijo-list-items-wrapper>
  <keijo-entity-list-item *ngFor="let item of items" [expandable]="true">
    <ng-template #primary>…</ng-template>
    <ng-template #secondary>…</ng-template>
    <ng-template #actions>…</ng-template>
  </keijo-entity-list-item>
</keijo-list-items-wrapper>
```

Per il **filtro + ricerca** in cima a lista/tabella usa `<keijo-search-bar>` con `[filterTabs]`.

Per le **azioni di riga** (icone modifica/elimina/visualizza), segui la convenzione di ordering documentata in `node_modules/@keijo/ui/README.md` → sezione **"Row action button ordering"**.

## 4. Dashboard e chart card

Per cruscotti, usa `<keijo-chart-card>` con projection slot. La libreria **non spedisce alcuna chart lib** — è scelta del progetto (ECharts, Chart.js, SVG fatto a mano).

```html
<keijo-chart-card title="Promozioni" size="L" [filterTabs]="periodTabs">
  <my-line-chart [data]="…" />
</keijo-chart-card>
```

**Regola layout** (`KEIJO-DASHBOARD-CHART-CARD-LAYOUT`): ogni riga totalizza **3 unità M** (la card `M` è quadrata = 1 unità, la `L` è doppia = 2 unità). Composizioni ammesse: **`M+M+M`**, **`L+M`**, **`M+L`**. Una riga da 2 unità (`M+M`) lascia la riga visivamente vuota; 4 unità sforano. Sotto `md` ogni card diventa full-width.

## 5. Modali e toast

**Modali**: usa `ModalService` (di keijo-ui), **non** `MatDialog`:

```ts
import { ModalService } from '@keijo/ui';

const modal = this.modal.open(MyDialogComponent, { data: { … } });
modal.afterClosed$.subscribe(result => …);
```

**Toast**: render una sola `<keijo-toast-notification>` a livello shell con un array `notifications: ToastNotification[]`. Un servizio centrale pubblica nuove toast (vedi il pattern usato in `src/app/services/toast.service.ts` quando presente).

---

## 6. Icone

Tree-shakeable, sempre `import` dal sotto-modulo `keijo-ui/icons`:

```ts
import { home, settings, person, addAd } from '@keijo/ui/icons';
```

Passa l'oggetto importato direttamente all'input `[icon]` del componente. **Non usare mai stringhe** (`icon="home"`). Sono disponibili ~3866 icone derivate da Material Symbols Rounded (outline + filled).

## 7. Posizionamento dei tasti (livello pagina)

### Regola generale: azioni d'entità → header

Tutte le **azioni legate all'entità della pagina** (CRUD: Nuovo, Salva, Elimina; secondarie: Esporta, Aggiorna, Filtri globali) vanno SEMPRE nell'`<keijo-header>` `[buttons]`. Mai dentro la pagina.

```ts
// Esempio: pagina "Clienti" (list), primary = Nuovo (UNA parola)
headerButtons: HeaderActionButton[] = [
  { id: 'create',  icon: add,         label: 'Nuovo',    tooltip: 'Nuovo cliente' },  // primary (rightmost)
  { id: 'export',  icon: cloudUpload, label: 'Esporta',  tooltip: 'Esporta CSV' },
];
```

L'header le pone in alto a destra automaticamente: `buttons[0]` = primary (mostra label), gli altri = icon + tooltip.

**Regola label primary**: la `label` del button primary è una **sola parola** (`Nuovo`, `Salva`, `Esporta`, `Elimina`). Mai due (no `Nuovo cliente`, no `Salva modifiche`). Il `tooltip` può portare il contesto completo. Regola `KEIJO-HEADER-PRIMARY-SINGLE-WORD-LABEL`.

### Eccezione: solo se l'utente la chiede esplicitamente

Se serve un'azione **dentro la pagina** (es. "Approva" su una specifica sezione di un detail, contestualmente a quei dati), va racchiusa in un `<keijo-page-section-wrapper>` dedicato. Default = header. L'eccezione si applica solo se la richiesta è esplicita.

### Submit form

- **Form di entity CRUD** (Crea / Modifica una entità): il Submit va **SOLO** nell'header (es. label `Salva`). NIENTE button in fondo al form — il back button up-one-level dell'header è l'implicit cancel.
- **Form NON-entity** (filter, search, settings sub-form, dialog): CTA submit in fondo al form-wrapper allineata a destra, `accent`/`success` per il primary.

### Row actions

Per il posizionamento **intra-riga** (modifica / elimina / visualizza dentro `entity-list-item` o `keijo-table`), apri `node_modules/@keijo/ui/README.md` → **"Row action button ordering"**.

### Back button dell'header

**Visibilità** (`KEIJO-HEADER-BACK-HIDDEN-ON-SIDEBAR-ROUTES`): il back chevron è nascosto di default sulle rotte presenti in sidebar (destinazioni top-level: l'utente ci arriva via sidebar, non c'è un livello superiore semantico). Visibile su tutte le altre rotte.

**Override per-rotta**: aggiungi `data: { showBackButton: true | false }` nella route definition.
```ts
{ path: 'profilo',       data: { showBackButton: true } }   // forza visibile anche se in sidebar
{ path: 'wizard/step-1', data: { showBackButton: false } }  // forza nascosto su rotta non-sidebar
```
Lo shell composer in `app.component.ts` legge `ActivatedRoute.snapshot.data.showBackButton` del leaf e lo applica come override.

**Comportamento al click**: `<keijo-header>` espone `(back)`. Lo shell composer gestisce navigando **un livello in su nel path** (es. `/clienti/123/edit` → `/clienti/123` → `/clienti` → `/dashboard`), **non** la history del browser. Pattern prevedibile indipendentemente da come l'utente è arrivato.

L'icona del back è un chevron-left "heavy" (Material Symbols Rounded weight 700) cablata nel componente header — non è sovrascrivibile, e il suo peso visivo è scelto per matchare il titolo bold a fianco.

### Geometria dell'header

L'altezza dell'header è `3.125rem` (50px), coincidente con l'altezza massima del logo PNG sidebar — header e logo condividono la stessa baseline orizzontale a cavallo del confine sidebar/content. L'header non ha padding a sinistra (il wrapper `.header-row` nello shell composer ha `padding: 0.625rem 0.625rem 0.625rem 0`): il chevron del back è flush col bordo sinistro del content, sulla stessa colonna verticale del contenuto pagina sottostante. Regole `KEIJO-HEADER-HEIGHT-MATCHES-LOGO` e `KEIJO-HEADER-FLUSH-LEFT-NO-PADDING`.

## 8. Anti-pattern

- ❌ **Non importare `@angular/material` o `@angular/cdk`**. keijo-ui è zero-deps.
- ❌ **Non caricare Material Symbols via CDN**. Usa `<keijo-icon>` + icone da `keijo-ui/icons`.
- ❌ **Non usare `MatDialog`**. Usa `ModalService` di keijo-ui.
- ❌ **Non aggiungere font diversi da quello già configurato in `styles.scss`**, a meno di necessità motivate.

## 9. Logo

I file `src/assets/logo/logo.png` e `src/assets/logo/logo-collapsed.png` sono **placeholder** — sostituiscili con il logo del progetto. Non modificare i path o i binding `[logoExpandedUrl]` / `[logoCollapsedUrl]` su `<keijo-sidebar>` in `app.component.ts`.

Specifiche:
- `logo.png`: ≤ 200 × 50 px, **PNG con sfondo trasparente** (mostrato quando la sidebar è espansa)
- `logo-collapsed.png`: ≤ 40 × 40 px, **PNG con sfondo trasparente** (mostrato quando collassata)
